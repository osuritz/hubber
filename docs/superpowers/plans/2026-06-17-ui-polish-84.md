# UI Polish Pass — Drafts icon, "no checks" CI state, refresh focus ring (#84) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> Branch: `fix/ui-polish-84` (off `main` @ `0919ae7`). TDD where the surface is testable (provider CI mapping); visual/AppKit items are build- + manual-verified. Gate with **`make ci`**; the `.githooks/pre-push` hook runs it on push (CI is manual-only). One PR → main.

**Goal:** Address the three UI-feedback items: (1) remove the redundant left doc-icon in the Drafts tab, (2) replace the misleading "pending" clock shown for PRs that have no CI checks with a neutral "no checks" marker, and (3) stop the Refresh button from drawing its focus ring when the popover opens (before any keyboard navigation).

**Architecture:** Introduce a first-class `PullRequestCI.noChecks` state so "no checks exist" is distinct from "checks pending"; both providers already detect the no-CI case (GitHub returns the `"No checks"` detail; GitLab has a null `headPipeline`) and now emit `.noChecks`, which renders as a neutral gray hollow-circle-with-dash badge instead of a clock. The Drafts left icon is deleted. The popover panel clears its first responder on open so AppKit doesn't focus-ring the first button until the user actually tabs.

**Tech Stack:** Swift 6.3, SwiftUI + AppKit (`NSPanel`/`NSHostingView`), SPM, XCTest.

**Issues:** Closes #84. The UI feedback: Drafts — drop the same-for-every-row left icon; Drafts right badge + Outgoing left badge show "pending" when a PR has no checks (e.g. docs-only); the Refresh button shows a focus box on open without keyboard nav.

---

## Coordinator decisions (do not relitigate)

1. **`.noChecks` is a real CI state, not a rendering hack.** Add it to `PullRequestCI` and thread it from the providers, rather than string-matching `ciDetail` in the view. The providers already know (GitHub: no `statusCheckRollup`; GitLab: null `headPipeline`).
2. **`.noChecks` only for genuinely-absent CI.** GitHub: the no-rollup and unrecognized-state branches (which already return `"No checks"`). GitLab: a null/absent pipeline (`mapCI(nil)`). Present-but-non-terminal pipeline statuses (`CREATED`/`PENDING`/`MANUAL`/`CANCELED`/`SKIPPED`/…) stay `.pending` — they are not "no checks". Running/passing/failing are unchanged.
3. **GitHub drafts: map to `.noChecks`, don't expand the query.** The drafts GraphQL query doesn't fetch CI today (it hardcodes `"not checked"`). Rather than add a `statusCheckRollup` fragment to the drafts query (scope creep), map the draft's CI to `.noChecks` so it shows the neutral marker instead of a clock. Fetching real per-draft CI is a possible follow-up. (GitLab drafts already fetch `headPipeline`, so they show real CI — only the null case changes.)
4. **Visual treatment = neutral gray hollow circle + minus** ("dash marker"), with the existing detail text ("No checks" / "no pipeline"). Keeps row alignment (the badge stays the leading element in Outgoing) and reads clearly as "no CI", distinct from the pending clock. New muted-gray token `ciNoChecks` (lighter than `ciPending`).
5. **Drafts left icon removed entirely**, including the now-unused `DraftDocIcon` struct and the `draftIcon` field in `RowDensity.cfg`.
6. **Focus-ring fix is AppKit-side and visual-only** — `panel.makeFirstResponder(nil)` after `orderFrontRegardless()`. No SwiftUI `@FocusState` is in play; the ring is AppKit's default key-view selection. Verified by running the app (not unit-testable).

        guard let status else { return .noChecks }
        switch status.uppercased() {

            return .failing
        case "RUNNING":
            return .running
